# Debug-Link verbessern: Routing, Mismatch, Code-Version, Anliegen 2000 Zeichen

Ziel: Die `/debug`-Seite (Link im Footer der Brief-Mail) zeigt mehr von dem, was wir ohnehin erheben. Keine neue Speicherung, keine DB-Migration, keine Vercel-Einstellung.

Datengrundlage (573 Reviews, `issueTextLength`): 600 Zeichen decken 44,7 % der Anliegen vollständig ab, 2000 Zeichen 97,9 %.

## Constraints

- Neue Payload-Felder optional, alte Base64-Links müssen weiter dekodieren und rendern.
- `issueTextPreview` bleibt aus dem Feedback-Token (`prepareLetterEmail` löscht es, unverändert lassen).
- Payload so klein wie möglich: Mismatch wird auf `/debug` aus vorhandenen Feldern abgeleitet, nicht als neues Feld gespeichert.
- Kein neues Logging, keine neuen Tabellen.
- Code-Stil der Umgebung beibehalten (deutsche Kommentare, gleiche Dichte).

## Task 1: Payload erweitern

files:
- web/src/lib/email/buildDebugPayload.ts
- web/src/lib/email/sendLetterEmail.ts (Interface `LetterDebugPayload`)
- web/src/lib/email/variantDebugPayload.ts

action:
1. `ISSUE_TEXT_PREVIEW_MAX` von 600 auf 2000.
2. Neues optionales Feld `codeVersion?: string` in `LetterDebugPayload` und `LetterVariantDebugPayload`. Wert: `process.env.VERCEL_GIT_COMMIT_SHA?.slice(0, 7)`, Fallback `"unbekannt"`. Kleine exportierte Hilfsfunktion in `buildDebugPayload.ts` (z. B. `getCodeVersion()`), genutzt von `buildDebugPayload`, `buildResendDebugPayload` und `buildVariantDebugPayload`.

verify: `npx jest src/__tests__/debugPayload.test.ts` (aus `web/`)

done: Payload enthält `codeVersion`, Anliegen-Auszug bis 2000 Zeichen.
