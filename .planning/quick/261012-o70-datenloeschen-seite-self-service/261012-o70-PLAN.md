## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mail link to page (GET) | untrusted token in the query string; can be prefetched by mail scanners, forwarded or leaked |
| browser to Server Action (POST) | untrusted input object; an attacker can send arbitrary fields |
| server to Supabase (service role) | bypasses RLS; any wrong filter deletes other people's data |
| server to logs (Vercel) | errors must not carry email addresses or tokens |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-o70-01 | Elevation of Privilege | deleteDataAction | critical | mitigate | Input schema is strict { token } only; the deleted address comes solely from verifyDataDeletionToken; a test proves an extra email field yields invalid_link with zero Supabase calls (Task 1) |
| T-o70-02 | Spoofing | dataDeletion/token.ts | high | mitigate | HMAC-SHA256 with timingSafeEqual and a length check, zod envelope with purpose literal "data_deletion" and v 1, 90-day TTL, 30 s future skew, 4096-char cap; tests for tampering, expiry and skew (Task 1) |
